# Abgabe-Checkliste

## Steuerungsfundament

- [ ] Constitution mit Architektur, Konvention und harter Grenze vor Implementierung erstellt.
- [ ] Spec mit mindestens zwei begründeten Randfällen vor Implementierung erstellt.
- [ ] Zwei vermiedene stille Entscheidungen erklärt.
- [ ] Festgelegt, welche Spec-Aussagen verbindlich sind und wie Änderungen freigegeben werden.

## Werkzeugwahl

- [ ] Skill, MCP und direkte Definition am tatsächlichen Bedarf verglichen.
- [ ] Mindestens eine passende Option eingerichtet und wirklich ausgeführt.
- [ ] Definition/Implementierung und Ein-/Ausgabe beigelegt.
- [ ] Zusätzlichen Aufwand schwererer Alternativen konkret begründet.

## Umsetzung und Kontext

- [ ] Plan vor Codeänderung gegen den Vertrag geprüft und bestätigt.
- [ ] Code lokal lauffähig, neue Tests aussagekräftig.
- [ ] Mindestens zwei echte Sitzungen dokumentiert.
- [ ] Eigenes Handover mit tatsächlichen Ergebnissen und offenen Punkten gespeichert.
- [ ] Konkrete Kontextauswahl und ihre Abwägung erklärt.
- [ ] Eigenes Entscheidungsprotokoll während der Arbeit geführt; Muster nicht als Verlauf ausgegeben.

## Verifikation

- [ ] Frische Prüfsitzung oder andere prüfende Person eingesetzt.
- [ ] Spec, Constitution, vollständigen Diff und relevanten Bestand geprüft.
- [ ] Jeden Spec-Punkt einer konkreten Prüfung zugeordnet.
- [ ] Nach bislang ungetesteten Fällen gesucht und Ergebnis dokumentiert.
- [ ] Bei nachgewiesenem Fehler aussagekräftigen roten/grünen Testlauf gesichert.
- [ ] Tatsächliche Testausgabe und Laufumgebung beigelegt.
- [ ] Jede Codeänderung verständlich erklärt.

## Lieferung

- [ ] README mit frischer Installation und Ausführung.
- [ ] Code und Tests ohne node_modules.
- [ ] Constitution, Spec, Plan, Entscheidungsprotokoll, Handover, Verifikationsmatrix.
- [ ] Vollständiger eigener Diff gegenüber dem tatsächlichen Ausgangsstand.
- [ ] Eine Abwägung und eine verbleibende Grenze reflektiert.
- [ ] Keine erfundenen Ergebnisse, Sitzungen oder unabhängigen Prüfungen.
